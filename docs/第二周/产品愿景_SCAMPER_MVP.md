# 第二周交付：产品愿景 · SCAMPER · MVP

> 项目：基于面向对象的矿山安全管理系统（RSM）
> 交付：三页 / 五分钟讲解
> 日期：2026 年 11 月

---

## 第 1 页 · 产品愿景（Moore 模板）

| 模板 | 填写内容 |
| --- | --- |
| **FOR** | 矿山企业的一线安全员、现场员工与安全管理人员 |
| **WHO** | 需要把“风险分级管控 + 隐患排查治理”落到每个班次，却仍靠纸质台账、电话和微信群，巡查难留痕、隐患难闭环 |
| **THE** | 矿山安全风险预控与隐患排查系统（RSM） |
| **THAT** | 用作业计划自动生成巡查清单，手机扫码逐项拍照，隐患从上报、指派、整改到复查全程可追溯 |
| **UNLIKE** | 通用 OA、纸质检查表，或只做单一隐患上报的工具 |
| **OUR PRODUCT** | 以“作业—风险—巡查—隐患”一条主线串起双重预防机制，现场只带一部手机，管理层只看一张今日看板 |

> 填写口径：严格按 Moore 模板六行填写，不额外扩写口号；产品全貌可以更大，但这一页只回答“为谁、解决什么、凭什么不同”。

## 第 2 页 · SCAMPER 七问工作单

### 2.1 七问与想法（15 条）

| 字母 | 七问 | 想法 |
| --- | --- | --- |
| **S** 替代（Substitute） | 有什么可以替代？ | **S1** 用微信小程序 + 巡查点二维码替代纸质巡查卡：扫码即出风险、检查项和上次问题。<br>**S2** 用“作业计划”作为巡查任务的唯一入口，替代安全员手工排班和电话通知。 |
| **C** 组合（Combine） | 可以和什么组合？ | **C1** 把风险库、待查项、巡查清单、隐患台账合成一条数据链：同一个风险对象贯穿作业前、中、后。<br>**C2** 把隐患整改与班组交接班组合：未闭环隐患自动进入下一班交接清单。 |
| **A** 借鉴（Adapt） | 可以借鉴什么？ | **A1** 借鉴外卖/工单状态机：隐患 = 待审核 → 待指派 → 整改中 → 待复查 → 已闭环，超时自动标红。<br>**A2** 借鉴“健康打卡”的三步交互：选清单 → 拍照 → 提交，单个巡检项不超过 3 步。 |
| **M** 放大（Modify / Magnify） | 哪些可以放大？ | **M1** 放大拍照留痕：每项必拍，照片自动带时间、地点、巡检人水印，作为纸质签字的替代证据。<br>**M2** 放大管理层视角：只做“今日未完成、超期未整改、A 级作业”三个数字，不做复杂报表。 |
| **P** 他用（Put to other uses） | 还能用来做什么？ | **P1** 风险库复用到班前会：班组长扫码查看当班风险与管控措施，生成 1 分钟安全交底。<br>**P2** 巡查与隐患数据复用到培训与考核：按高频隐患自动生成下月培训主题。 |
| **E** 消除（Eliminate） | 可以去掉什么？ | **E1** 砍掉重型后台：MVP 不做菜单/按钮级 RBAC、部门岗位、字典、日志、定时任务、代码生成。<br>**E2** 砍掉非核心终端能力：不做大屏、事故地图、报表导出、传感器/人员定位/政府平台对接。 |
| **R** 重排/反转（Rearrange / Reverse） | 顺序或方向可以反过来吗？ | **R1** 反转审批：B/C/D 级作业自动通过，只有 A 级进入审批，避免流程卡住现场。<br>**R2** 反转隐患来源：不只等安全员巡查，先开放全员随手拍，再统一进入审核池。<br>**R3** 反转建库顺序：不要求风险库一次建全，作业填报时从库中选择并强制关联，在使用中补齐。 |

### 2.2 投票：2 条差异化方向

投票口径：**差异化程度 × 两周内可被现场验证**。方向 A 与方向 B 不是两个产品，而是同一闭环的两端：A 保证“有计划地查”，B 保证“没计划也能报”。

| 方向 | 组合想法 | 一句话主张 | 入选理由 |
| --- | --- | --- | --- |
| **A. 作业驱动的巡查闭环** | S2 + C1 + R1 + M1 | 每一次巡查都由当班作业计划触发，风险、清单、照片、隐患共用同一条数据链。 | 直接命中“风险库与作业脱节、巡查难留痕”的根因；通用 OA 难复制；两周试点可验证。 |
| **B. 零门槛全员上报** | R2 + A1 + S1 + A2 | 把隐患上报压缩成“拍照 + 选位置 + 提交”，让不会用电脑的现场员工也愿意报。 | 解决数据来源和参与度；与 A 共用隐患工单，边际成本低；能形成“人人都是安全员”的网络效应。 |
| 备选：管理层实时看板 | M2 | 一块屏看清风险态势。 | 有价值，但依赖 A/B 先产生足够数据，放到二期。 |

## 第 3 页 · MVP 定义

**一句话：用两周证明，现场愿意用手机完成“作业驱动的拍照巡查 + 隐患闭环”，并且这能替代纸质台账。**

### 3.1 三句话

**01 核心动作。** 现场安全员打开小程序，按当日作业生成的清单扫码巡查、逐项拍照；发现隐患就地上报，由隐患主管指派、整改人反馈、复查人确认，形成一条可追溯的闭环。

**02 砍掉什么。** 砍掉菜单/按钮级 RBAC、部门岗位/字典/日志/定时任务、Excel 批量导入导出、统计报表与大屏、事故地图、短信/推送、传感器与政府平台对接；只保留 4 个固定角色（现场员工、安全员、隐患主管、管理员）、1 个矿区、基础风险库与巡查点、作业→清单→隐患闭环、图片上传和 3 个数字的今日看板。

**03 验证哪个阶段。** 在 1 个矿区、2 个班组、20 名现场人员、30 个巡查点做 2 周现场试点，验证“拍照巡查能否替代纸质台账、隐患能否在 3 天内闭环”，而不是验证高并发、多租户或完整权限体系。

### 3.2 保留 / 砍掉

| 保留（MVP 必须） | 砍掉（本期不做） |
| --- | --- |
| 4 个固定角色：现场员工、安全员、隐患主管、管理员 | 菜单/按钮级 RBAC、部门/岗位/字典/操作日志/定时任务/代码生成 |
| 1 个矿区：人员、区域、巡查点、A/B/C/D 风险库 | 多矿区、多租户、组织架构维护 |
| 作业计划：手工新建、关联风险、A 级审批（隐患主管） | Excel 批量导入导出、复杂排班、跨班组调班 |
| 由作业生成待查项与当日巡查清单 | 轨迹回放、NFC/蓝牙巡检、传感器、人员定位、监管平台对接 |
| 扫码巡查、逐项拍照、水印、弱网暂存 | 隐患知识库、自动定级、智能推荐整改措施 |
| 隐患上报（巡查 + 随手拍）→ 审核 → 指派 → 整改 → 复查 | 文件管理、多格式附件、视频 |
| 图片上传（OSS）、微信登录 + 员工账号绑定 | 短信验证码、密码体系、SSO、多端审批 |
| 今日看板 3 个数字、审计字段 | 实时大屏、事故地图、统计报表、报表导出、消息推送 |

### 3.3 验证指标与停止规则

| 指标 | 通过线 | 说明 |
| --- | --- | --- |
| 巡查完成率 | ≥ 80% | 当日应查清单中，按时完成并拍照的比例 |
| 隐患拍照上报率 | ≥ 70% | 上报隐患中，带现场照片与定位的比例 |
| 平均闭环时长 | ≤ 3 天 | 从隐患审核到复查确认的中位时长 |
| 单个巡查点耗时 | ≤ 3 分钟 | 从扫码到提交完成的平均时长 |

**通过** → 扩到 5 个班组，进入二期（统计、大屏、多矿区）。**未通过** → 只改交互、离线同步、提醒，不扩功能。**红线** → 连续两周巡查完成率低于 50%，暂停开发，跟班观察真实工作流。
